# 出站配置同机 A/B（2026-11-26）

## 环境

- Windows `10.0.26300`，.NET SDK `10.0.402`
- 8 个逻辑处理器
- Server GC、并发 GC、分层 PGO
- 数据来自本机开发环境，不是发布性能声明

## 方法

目标格：QoS 1 / 100 订阅者 / 64 KiB，单发布者，预热 5 秒、测量 20 秒、
3 轮交替（基线先跑与候选先跑各占一轮）。每个变体使用同一负载驱动、
同一 Broker 程序集，只改一项配置：

```powershell
dotnet benchmarks/MqttZero.BrokerBenchmarks/bin/Release/net10.0/MqttZero.BrokerBenchmarks.dll ab `
  --baseline-broker <dll> --candidate-broker <dll> `
  --baseline-event-loop-shards 0 --candidate-event-loop-shards 4 `
  --qos 1 --subscribers 100 --payload 65536 --publishers 1 `
  --warmup 5 --seconds 20 --rounds 3 --max-pending 1024
```

## 结果

自动 Shard 数为 8，自动 Kestrel I/O 队列数为 8。

| 实验 | 基线 | 候选 | 端到端吞吐变化 | 交付 p99 比值 | 失败 / 缺口 / 重复 |
|---|---|---:|---:|---:|---|
| Shard 数 | 8（自动） | 4 | -1.5% | 1.138 | 0 / 0 / 0 |
| Kestrel I/O 队列 | 8（自动） | 4 | -3.7% | 0.928 | 0 / 0 / 0 |
| 出站批次 | 128 条 / 512 KiB / 500 µs | 64 条 / 256 KiB / 250 µs | +0.6% | 0.938 | 0 / 0 / 0 |

三项都没有达到主目标格 10% 的吞吐提升门槛，因此**不修改任何默认配置**。

I/O 队列减半与更小批次都让交付 p99 略有改善（分别 -7.2% 与 -6.2%），
但吞吐同时下降（前者）或基本持平（后者）。按开发环境证据，这些只能
作为特定部署的调优建议，不能作为默认值变更依据。
